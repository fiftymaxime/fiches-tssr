SAUVEGARDE · VEEAM B&R

Veeam Backup & Replication — Job VM + restauration

Cible : Windows Server dédié Veeam, 8+ Go RAM, stockage backup séparé de la prod.

1Installer Veeam B&R

Télécharger l'ISO Community Edition (gratuit, 10 VM) sur veeam.com
Monter l'ISO → Setup.exe
Choisir :
  - Veeam Backup & Replication : Install
  - License : Community (ou charger la clé Enterprise)
  - Prerequisites installés automatiquement (.NET, SQL Express)
  - Options par défaut

2Premier lancement

Veeam Backup & Replication Console
Connect to : localhost (backup service running as System)

3Ajouter le vCenter ou hôte ESXi

Backup Infrastructure → Managed servers → Add server → VMware vSphere
  DNS/IP    : vcenter.monlab.local (ou esxi01.monlab.local)
  Credentials : compte service Veeam (droit "Administrator" sur vCenter)
  Save

4Ajouter un repository de sauvegarde

Backup Infrastructure → Backup repositories → Add
  Type      : Direct attached storage / SMB share / NFS
  Server    : IP ou UNC
  Path      : \\SRV-BACKUP\Veeam
  Credentials : compte avec droits écriture

5Créer un job de sauvegarde

Home → Backup Job → Virtual machine

Name         : Job-Prod-Quotidien
Virtual machines : Add → sélectionner VMs ou dossier
Storage      : Backup repository = SRV-BACKUP
  Retention  : keep 14 restore points
  Advanced   : ✔ Enable inline data deduplication
              : ✔ Enable compression (Optimal)
Guest processing : ✔ Enable application-aware processing
                 : Credentials Guest OS
Schedule     : Daily at 22:00
Finish → ✔ Run the job when I click Finish

6Restauration - VM complète (Instant Recovery)

Home → Restore → VMware vSphere → Restore from backup → Entire VM

Sélectionner le restore point → Instant Recovery
Destination : ESXi hôte + datastore
  → La VM démarre en quelques secondes depuis le backup
  → Puis migration Storage vMotion vers le stockage prod en tâche de fond

7Restauration granulaire - fichier unique

Home → Restore → Guest OS files (Windows/Linux/Mac)
  Sélectionner le restore point
  Naviguer dans l'arbo → clic droit → Restore
  Options : Overwrite / Keep both / Restore to another location

8Restauration - Application Item (AD, Exchange, SQL)

Home → Restore → Microsoft Active Directory (par exemple)
  Restaurer un utilisateur/OU supprimé sans restaurer tout le DC

9SureBackup (test automatique de restauration)

Backup Infrastructure → SureBackup → Application Groups
  Créer un groupe de VMs à tester (AD, SQL, Web)

Home → SureBackup → SureBackup Job
  Boot chaque VM dans un lab isolé (bulle réseau)
  Vérifie : boot OK, heartbeat, ping, application accessible
  → Rapport email automatique

10Politique 3-2-1-1-0

3 copies (1 originale + 2 backup)
2 supports différents (disque + tape/cloud)
1 hors-site (offsite)
1 immuable (contre ransomware : hardened repo Linux ou cloud object lock)
0 erreur (jobs verts + tests SureBackup)

11Configurer un hardened repository (anti-ransomware)

Serveur Linux dédié avec compte non-root, single-use, XFS + reflink :
  Backup Infrastructure → Add → Linux
  Cocher "Single-use credentials for hardened repository"
  Path : /mnt/backup
  → Immutabilité 14 jours (les fichiers ne peuvent pas être supprimés)
3-2-1 STRICT — Une sauvegarde qui n'a jamais été testée n'existe pas. Programmer un SureBackup hebdo + un test de restauration réel manuel tous les mois. Un backup corrompu qu'on découvre au moment de l'incident = catastrophe.
