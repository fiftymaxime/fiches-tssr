LINUX · WEB / TLS

Let's Encrypt + Nginx

Prérequis : nom de domaine public pointant vers l'IP publique du serveur, ports 80 et 443 ouverts.

1Installer Nginx

sudo apt update
sudo apt install nginx -y
sudo systemctl enable --now nginx

2Créer un vhost pour ton site

sudo nano /etc/nginx/sites-available/monsite.conf

server {
    listen 80;
    server_name monsite.exemple.com www.monsite.exemple.com;
    root /var/www/monsite;
    index index.html;
}

sudo ln -s /etc/nginx/sites-available/monsite.conf /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

3Vérifier la résolution DNS

dig +short monsite.exemple.com
# Doit retourner l'IP publique de ce serveur

4Installer Certbot

sudo apt install certbot python3-certbot-nginx -y

5Demander le certificat (auto-config Nginx)

sudo certbot --nginx -d monsite.exemple.com -d www.monsite.exemple.com \
  --agree-tos --email admin@exemple.com --redirect --no-eff-email

Certbot modifie automatiquement la conf Nginx : ajoute le vhost 443 et redirige 80 → 443.

6Vérifier le certificat

curl -I https://monsite.exemple.com
openssl s_client -connect monsite.exemple.com:443 -servername monsite.exemple.com < /dev/null | openssl x509 -noout -dates

7Test de renouvellement (sans réellement renouveler)

sudo certbot renew --dry-run

8Cron de renouvellement automatique

# Certbot installe déjà un timer systemd - vérifier
systemctl list-timers | grep certbot

# Sinon, ajouter manuellement dans /etc/crontab
0 3 * * * root certbot renew --quiet --deploy-hook "systemctl reload nginx"

9Renforcer la conf TLS (Mozilla intermediate)

sudo nano /etc/nginx/sites-available/monsite.conf

server {
    listen 443 ssl http2;
    server_name monsite.exemple.com;

    ssl_certificate     /etc/letsencrypt/live/monsite.exemple.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/monsite.exemple.com/privkey.pem;

    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_prefer_server_ciphers off;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384;
    ssl_session_cache shared:MozSSL:10m;
    ssl_session_timeout 1d;
    ssl_session_tickets off;

    add_header Strict-Transport-Security "max-age=63072000" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
}

10Tester le score TLS

https://www.ssllabs.com/ssltest/analyze.html?d=monsite.exemple.com
# Objectif : note A ou A+
LIMITES LET'S ENCRYPT — 50 certificats par domaine principal par semaine. Ne pas mettre certbot en boucle. Pour des tests, utiliser --staging.
