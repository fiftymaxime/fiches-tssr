FORENSIC · ANALYSE MENACES

Wireshark — Analyse sécurité (IOC, exfil, C2)

1Détecter un scan réseau (SYN scan)

# Beaucoup de SYN sans handshake complet vers plusieurs ports
tcp.flags.syn == 1 and tcp.flags.ack == 0

# Statistiques → Conversations → TCP
# Une IP avec 100+ conversations vers un même hôte = suspect

2Scan ARP (reconnaissance locale)

arp.opcode == 1

# Une source qui envoie beaucoup de "who has" en rafale = scan ARP

3Extraire des identifiants en clair

http.authbasic                         # auth HTTP Basic (base64)
ftp.request.command == "USER" or ftp.request.command == "PASS"
telnet
pop.request.command == "USER" or "PASS"
imap                                    # voir "LOGIN"

4Extraire des fichiers transférés

File → Export Objects → HTTP / SMB2 / IMF / FTP-DATA / TFTP
  → Sauvegarder → soumettre le hash à VirusTotal

# Calculer le hash SHA256 d'un fichier extrait
sha256sum fichier_extrait.exe

5Détecter un beaconing C2 (Command & Control)

Signes typiques :
  - Connexions périodiques (même intervalle) vers une même IP externe
  - Petites tailles constantes (heartbeat)
  - Souvent HTTPS/443 ou DNS

# Voir intervalles réguliers
Statistics → I/O Graph → filtrer par ip.dst == IP_SUSPECT
  Régularité toutes les 30s / 60s → beaconing probable

6Analyse DNS suspecte

# Requêtes vers des domaines aléatoires (DGA - Domain Generation Algorithm)
dns.qry.name

# Exfiltration via DNS (requêtes très longues)
dns.qry.name.len > 50

# Requêtes vers TXT records inhabituelles
dns.qry.type == 16

7Analyse TLS — SNI et JA3

# Nom des sites visités en HTTPS (SNI en clair)
tls.handshake.extensions_server_name

# Voir les certificats reçus
tls.handshake.type == 11

# Empreinte JA3 du client (identifie le malware/outil)
# Nécessite plugin Wireshark ou Zeek pour extraction

8Détecter du tunneling (ICMP, DNS)

# Trafic ICMP anormalement gros = tunneling data
icmp and data.len > 64

# Grosses requêtes DNS TXT = potentiellement DNS tunneling (dnscat2, Iodine)
dns.qry.type == 16 and dns.qry.name.len > 100

9Extraire IOC pour enquête

# Toutes les IP externes contactées
Statistics → Endpoints → IPv4 → cocher "Limit to display filter"
  → Copier → soumettre chaque IP à VirusTotal / AbuseIPDB

# Tous les domaines DNS résolus
tshark -r capture.pcap -Y dns -T fields -e dns.qry.name | sort -u

10Reconstitution d'une session (HTTP, TLS déchiffré si clés dispo)

Follow → HTTP Stream / TLS Stream

# Déchiffrer TLS avec les clés (nécessite variable SSLKEYLOGFILE côté client)
Edit → Preferences → Protocols → TLS
  (Pre)-Master-Secret log filename : /chemin/vers/sslkeys.log

11Timeline de l'incident

Statistics → Capture File Properties
  Voir "First packet" et "Last packet"

Menu View → Time Display Format → UTC Date and Time
  → Permet d'aligner avec les logs SIEM
CHAÎNE DE PRÉSERVATION — En cas d'incident réel, préserver le pcap original (hash SHA256), travailler sur une copie. Documenter chaque manipulation (date, opérateur, outil). Un .pcap peut être une preuve judiciaire.
