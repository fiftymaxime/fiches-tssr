SIEM · DÉTECTION

Sigma — Règles de détection universelles

Sigma = format YAML standardisé pour écrire une règle de détection une fois, puis la convertir vers n'importe quel SIEM (Splunk, ELK, Sentinel, QRadar, Wazuh...).

1Cloner le dépôt SigmaHQ

git clone https://github.com/SigmaHQ/sigma.git
cd sigma/rules/

Contient +3000 règles maintenues par la communauté (Windows, Linux, Cloud, Réseau, macOS).

2Structure d'une règle Sigma (YAML)

title: Suspicious PowerShell Encoded Command
id: 12345678-abcd-efgh-ijkl-1234567890ab
status: stable
description: Détecte l'utilisation de -EncodedCommand (obfuscation courante)
author: Toi
date: 2026/07/25
logsource:
  category: process_creation
  product: windows
detection:
  selection:
    Image|endswith: '\powershell.exe'
    CommandLine|contains: '-EncodedCommand'
  condition: selection
level: high
tags:
  - attack.execution
  - attack.t1059.001

3Installer pySigma + backends

pip install --break-system-packages pysigma pysigma-backend-elasticsearch \
  pysigma-backend-splunk pysigma-backend-wazuh pysigma-pipeline-sysmon

4Convertir une règle vers ELK (Lucene)

sigma convert -t lucene -p sysmon rules/windows/process_creation/proc_creation_win_susp_powershell.yml

5Convertir vers Splunk SPL

sigma convert -t splunk -p sysmon rules/windows/...

6Convertir vers Wazuh

sigma convert -t wazuh -p sysmon rules/windows/...

7Convertir un dossier complet

sigma convert -t lucene -p sysmon -r rules/windows/ -o out.txt

8Déployer dans le SIEM

# ELK - créer une detection rule
Kibana → Security → Rules → Create new rule
  Rule type : Custom query
  Custom query : (coller la requête convertie)
  Severity : High
  Investigation guide : lien vers la règle Sigma d'origine

# Wazuh - ajouter les règles converties dans
/var/ossec/etc/rules/local_rules.xml

9Tester une détection avec Atomic Red Team

# Installer sur poste de test (jamais en production)
Install-Module -Name invoke-atomicredteam -Scope CurrentUser

# Simuler T1059.001 (PowerShell encoded command)
Invoke-AtomicTest T1059.001 -TestNumbers 1

# Vérifier que l'alerte remonte dans le SIEM

10Écrire sa propre règle

Copier une règle existante proche du besoin → adapter :
  - logsource       (category + product)
  - detection       (champs à matcher)
  - condition       (logique)
  - tags MITRE ATT&CK

Valider :
sigma check ma_regle.yml
MÉTHODE — Toujours tester en dev avant de déployer une nouvelle règle Sigma en prod. Une règle mal ciblée peut noyer le SOC sous les faux positifs.
