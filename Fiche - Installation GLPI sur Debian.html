Installation de GLPI 11 sur Debian 13

Vérifié le 25/08/2026 — GLPI 11.0.8 sur Debian 13 « Trixie » (PHP 8.4, MariaDB). GLPI 11 exige PHP 8.2 minimum ; Debian 13 fournit PHP 8.4, qui convient.

Ce qui change depuis GLPI 10 — trois points font échouer l'ancienne procédure :
PointGLPI 10GLPI 11
Racine weble dossier glpi/obligatoirement glpi/public/
Extension PHP—bcmath devient obligatoire
Commande consoleglpi:system:check_requirementssystem:check_requirements

Phase 1 — Serveur LAMP

1Mettre à jour le système

sudo apt update && sudo apt upgrade -y

2Installer Apache, MariaDB, PHP et les extensions

sudo apt install -y apache2 mariadb-server libapache2-mod-php \
  php php-cli php-mysql php-curl php-gd php-intl php-mbstring \
  php-xml php-bcmath php-zip php-bz2 php-ldap php-opcache

Vérifier que tout est chargé :

php -m | grep -E 'mysqli|curl|gd|intl|mbstring|bcmath|zlib|openssl|dom'
Pièges de nommage. Le paquet est php-mysql — il fournit à la fois mysqli et pdo_mysql. Le paquet php-mysqli n'existe pas, et une seule mauvaise entrée fait échouer toute la commande apt install. De même, php-xmlrpc a disparu : l'extension a été sortie du cœur de PHP 8.
Sur Debian 13, les paquets php-* pointent vers PHP 8.4. Écrire php8.4-mysql revient au même, et n'est utile que si plusieurs versions de PHP cohabitent.

Phase 2 — Base de données

3Sécuriser MariaDB

sudo mysql_secure_installation

Répondre Y à toutes les questions de sécurité et définir un mot de passe root.

4Créer la base et l'utilisateur GLPI

sudo mariadb -u root -p

À l'invite MariaDB [(none)]> :

CREATE DATABASE glpidb CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'glpiuser'@'localhost' IDENTIFIED BY 'MotDePasseFort';
GRANT ALL PRIVILEGES ON glpidb.* TO 'glpiuser'@'localhost';
FLUSH PRIVILEGES;
EXIT;

5Charger les fuseaux horaires dans MariaDB

sudo mysql_tzinfo_to_sql /usr/share/zoneinfo | sudo mariadb mysql

sudo mariadb -e \
  "GRANT SELECT ON mysql.time_zone_name TO 'glpiuser'@'localhost'; FLUSH PRIVILEGES;"

Sans cette étape, GLPI signale les fuseaux horaires comme non disponibles et l'étape 12 échoue.

Phase 3 — Déploiement de GLPI

6Télécharger et extraire GLPI 11

cd /tmp
wget https://github.com/glpi-project/glpi/releases/download/11.0.8/glpi-11.0.8.tgz
sudo tar -xzf glpi-11.0.8.tgz -C /var/www/html/

L'archive crée /var/www/html/glpi. Vérifier la dernière version sur github.com/glpi-project/glpi/releases — la branche 10 s'arrête à 10.0.26 et n'évolue plus qu'en correctifs.

La documentation officielle place plutôt GLPI dans /var/www/glpi, hors de la racine web par défaut. Les deux fonctionnent : ce qui compte, c'est que le DocumentRoot pointe sur le sous-dossier public et sur rien d'autre.

7Attribuer les droits à Apache

sudo chown -R www-data:www-data /var/www/html/glpi
sudo find /var/www/html/glpi -type d -exec chmod 755 {} \;
sudo find /var/www/html/glpi -type f -exec chmod 644 {} \;
sudo chmod -R 775 /var/www/html/glpi/files

Les dossiers files et config doivent être inscriptibles par le serveur web ; le reste reste en lecture seule.

Phase 4 — VirtualHost Apache

8Créer le VirtualHost pointant sur public

sudo nano /etc/apache2/sites-available/glpi.conf
<VirtualHost *:80>
    ServerName glpi.local
    DocumentRoot /var/www/html/glpi/public

    <Directory /var/www/html/glpi/public>
        Require all granted
        AllowOverride All

        RewriteEngine On
        RewriteCond %{HTTP:Authorization} ^(.+)$
        RewriteRule .* - [E=HTTP_AUTHORIZATION:%{HTTP:Authorization}]
        RewriteCond %{REQUEST_FILENAME} !-f
        RewriteRule ^(.*)$ index.php [QSA,L]
    </Directory>

    ErrorLog ${APACHE_LOG_DIR}/glpi_error.log
    CustomLog ${APACHE_LOG_DIR}/glpi_access.log combined
</VirtualHost>
Le point critique de GLPI 11. L'archive ne contient aucun fichier .htaccess dans public/ : les règles de réécriture doivent figurer dans le VirtualHost. Sans elles, la page d'accueil s'affiche mais toute la navigation renvoie des erreurs 404.

9Activer le site et le module rewrite

sudo a2enmod rewrite
sudo a2dissite 000-default.conf
sudo a2ensite glpi.conf
sudo apache2ctl configtest
sudo systemctl reload apache2
sudo systemctl enable apache2 mariadb

Phase 5 — Installation de GLPI

10Vérifier les prérequis

cd /var/www/html/glpi
sudo -u www-data php bin/console system:check_requirements

Le rapport liste chaque extension manquante et chaque droit insuffisant : c'est le contrôle à passer avant d'aller plus loin.

En GLPI 10 la commande s'appelait glpi:system:check_requirements. Le préfixe glpi: a disparu en version 11 — un ancien script d'installation échoue donc silencieusement sur cette ligne.

11Installer la base en ligne de commande

sudo -u www-data php bin/console db:install \
  --db-host=localhost \
  --db-name=glpidb \
  --db-user=glpiuser \
  --db-password='MotDePasseFort' \
  --default-language=fr_FR \
  --no-interaction

Variante navigateur : ouvrir http://IP_SERVEUR/ — la racine du site, et non plus /glpi, puisque le VirtualHost pointe déjà sur public.

Comptes créés par défaut : glpi/glpi, tech/tech, normal/normal, post-only/postonly.

12Activer les fuseaux horaires dans GLPI

sudo -u www-data php bin/console db:enable_timezones

Phase 6 — Sécurisation obligatoire

13Supprimer le dossier d'installation

sudo rm -rf /var/www/html/glpi/install

Le dossier install/ est toujours présent dans l'archive 11.0.8 : il reste à supprimer une fois l'installation validée.

CRITIQUE — Modifier immédiatement le mot de passe des 4 comptes par défaut depuis Administration → Utilisateurs. Ces identifiants sont publics.
